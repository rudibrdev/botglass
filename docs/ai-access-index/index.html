The saved results below were produced by the original parser; raw robots.txt bodies were not retained, so parser corrections cannot be applied retroactively without a new measurement.

The original parser recorded 0 recognised train-ai preferences for / in 164 retrieved robots.txt responses. This is a historical result, not a corrected adoption estimate. 1 responses contained a Content-Usage line; unrecognised labels were recorded for launchpad.net (ai).

Crawl permission and usage preference are separate: allowing retrieval while declining training is valid, not a contradiction. These observations do not establish whether a crawler follows a preference.

How this was measured

  • Sample: the first 300 domains of the Tranco list (Tranco list, 2026-11-04).
  • One GET /robots.txt and one GET / per domain, 66 seconds total, no JavaScript executed.
  • A crawler counts as blocked when robots.txt disallows / for its token under the RFC 9309 rules botglass implements (longest match wins, * groups, crawl-delay ignored).
  • Content-Usage is read from the group that applies to a generic crawler for /, per the IETF aipref draft. Absent is not n.
  • Word counts are the text in the raw HTML — what a crawler that does not run JavaScript receives.
  • Limits: robots.txt can allow a crawler that never shows up, and can block one that ignores it. This measures declared access, not observed traffic. 136 domains did not return a successful robots.txt response; failures, denied requests and missing files are not evidence of absence.
